# Product Requirements Document (PRD)

**Project:** Food Production Cost Optimizer
**Phase 2:** Food Production Business Analytics and Visualization
**Status:** Implemented on branch `feature/business-analytics-visualization`

---

## 1. Background

The application is a food-production **decision-support** tool: it computes batch
economics (cost build-up, break-even, margins), runs what-if scenarios, optimizes
cost drivers, projects cost trends, and compares suppliers. All of these answer
the question *"what would this batch cost?"* for a single, hypothetical batch.

Missing was the **business-analytics** dimension: understanding a **portfolio**
of historical/planned batches — where cost is concentrated, which products earn
or lose money, how much is lost to wastage, and whether cost forecasts can be
trusted.

## 2. Problem statement

Operators can price a single batch but cannot answer portfolio-level questions:

- What is our overall margin and cost structure across all products?
- Which products and categories drive profit, and which destroy it?
- How much money is lost to wastage, and where?
- Are our cost forecasts accurate enough to act on?

## 3. Objectives

1. **Surface portfolio analytics** inside the existing product experience.
2. **Produce analysis-ready data** (flat dataset + CSV export) usable by other tools.
3. **Quantify insights by rule**, not opinion — every insight carries its numeric evidence.
4. **Provide independent, reproducible analysis** (Python EDA + forecast evaluation).
5. **Preserve** all existing functionality and the existing design language.
6. **Document** the work to academic/reference standard.

## 4. Non-goals

- No change to the cost-calculation formulas or existing screens.
- No multi-tenant/enterprise reporting, scheduling, or BI-server integration.
- No new runtime dependencies in the web app.
- The bundled dataset is **synthetic demo data**, not a real business dataset.

## 5. Users and use cases

| User | Use case |
| --- | --- |
| Production manager | See where cost is concentrated and which products to fix |
| Owner / analyst | Export the dataset, run EDA, judge forecast reliability |
| Academic reviewer | Reproduce every figure and metric from documented commands |

## 6. Requirements

### Functional

- **FR-1** An `Analytics` navigation entry opens a Business Analytics dashboard in the SPA.
- **FR-2** The dashboard shows: portfolio KPIs, cost-structure breakdown, product ranking,
  profit-margin distribution, wastage analysis, and an evidence-based insights panel.
- **FR-3** "Export Analysis CSV" downloads a UTF-8 CSV, one row per batch, with a stable
  ordered header.
- **FR-4** Insights are generated by documented, deterministic rules.
- **FR-5** The dataset/analytics degrade gracefully on empty data and zero denominators.
- **FR-6** A Python EDA script produces descriptive statistics and figures from the CSV.
- **FR-7** A Python evaluation script backtests the forecast models against naive baselines.

### Non-functional

- **NFR-1** No new runtime dependencies in the web app (charts use the existing CSS system).
- **NFR-2** Analytics logic is pure and unit-testable in isolation.
- **NFR-3** The Python layer is independent; the Node app runs without it.
- **NFR-4** No secrets or user identity are written to exports.
- **NFR-5** Outputs are reproducible from documented commands.
