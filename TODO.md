## Scope

Phase 2 adds a **business-analytics layer** on top of the existing decision-support app without
altering existing features. It delivers:

1. A Business Analytics dashboard surface inside the existing React SPA.
2. An analysis-ready flat dataset derived from stored batches, with CSV export.
3. A reproducible, independent Python EDA layer that consumes the exported CSV.
4. Evidence-based insights generated by explicit, documented rules.
5. A forecasting evaluation procedure (error metrics) with a Python reference implementation.
6. Academic/reference documentation.

Existing behaviour (calculator, optimizer, what-if, forecasting, suppliers, batches, auth) is
preserved. The Python layer is independent: the Node app runs with or without it.

## Design Decisions

- **DD-1 — Single-source analytics logic.** All aggregation/statistics/CSV logic lives in
  `client/src/utils/analyticsEngine.js` as pure ESM functions with no React/DOM imports, so it can
  be unit-tested from Node via dynamic `import()` from the existing server test runner. This avoids
  the client/server duplication already present in `calculator.js`.
- **DD-2 — No new runtime dependencies.** Charts reuse the existing CSS-variable design system and
  plain DOM (bars/tables). No charting library is added.
- **DD-3 — No invented data fields.** The engine consumes only fields already produced by
  `calculateBatchEconomics` plus batch metadata. Missing fields degrade to `0`/`null`, never crash.
- **DD-4 — Safe division.** Every ratio uses `safeDiv` which returns `0` for a zero/absent/non-finite
  denominator (empty datasets, zero quantity, zero revenue).
- **DD-5 — Export safety.** CSV export contains only batch economics and product metadata. No user
  identity, tokens, or secrets are exported.
- **DD-6 — Python independence.** `analysis/` is self-contained (`requirements.txt` + CLI scripts).
  It reads a CSV file produced by the app (or the committed sample) and never imports Node code.

## Formulas / Aggregation Rules

- `costPerUnit`, `grossProfit`, `profitMarginPercentage`, `roiPercentage`, `breakEvenQuantity` are
  taken from `batch.economics` (existing engine) — not recomputed here.
- `topIngredientSharePct = safeDiv(topIngredientCost, rawMaterialCost) * 100`.
- `wastageQuantity = batchQuantity - sellableQuantity`.
- Portfolio KPIs aggregate as:
  - `totalProductionCost = Σ totalProductionCost`
  - `totalRevenue = Σ totalRevenue`
  - `totalProfit = Σ grossProfit`
  - `avgUnitCost = safeDiv(totalProductionCost, Σ sellableQuantity)`
  - `portfolioMarginPct = safeDiv(totalProfit, totalRevenue) * 100`
  - `wastageSharePct = safeDiv(Σ wastageCost, totalProductionCost) * 100`
- Cost structure shares use a fixed 7-category taxonomy matching the Dashboard
  (raw materials, packaging, labour, energy + water, logistics, overheads, wastage loss).
- Insights are deterministic rules over the aggregate; each insight records the numeric evidence.

## Acceptance Criteria

- **AC-1** A new `Analytics` navigation tab is reachable and renders within the existing SPA styling.
- **AC-2** The dashboard shows portfolio KPIs, cost-structure breakdown, product ranking, margin
  distribution, wastage analysis, and an insights panel.
- **AC-3** "Export Analysis CSV" downloads a UTF-8 CSV with one row per batch and a stable, ordered,
  documented header (no secrets).
- **AC-4** The engine handles an empty dataset and zero-denominator inputs without throwing, and
  returns zeroed KPIs plus an explanatory insight.
- **AC-5** `npm test` passes (existing 11 tests + new analytics tests, 0 failures).
- **AC-6** `npm run build` (Vite) succeeds.
- **AC-7** `python analysis/eda.py` and `python analysis/forecast_eval.py` run on the committed sample
  data and print reproducible summaries (given the documented deps).
- **AC-8** Documentation covers PRD, architecture, methodology, data dictionary, EDA, evaluation, and
  decision log.
